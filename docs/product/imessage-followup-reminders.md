# Optional generic iMessage follow-up reminders

After a real first follow-up result, or from account Settings, the user may verify an enrolled Mac's own nongroup Messages thread. Destination verification and reminder delivery are separate decisions. The prior saved updates preference never authorizes delivery.

The first delivery scope is fixed: “Knapsack: a reviewed follow-up needs attention. Open Knapsack to review it.” A short opaque event reference is appended. Source excerpts, drafts, recipients, full briefings, groups, SMS and automatic replies are excluded. Consent authorizes at most five messages from the verified self-thread to confirm the destination per attempt. Reminders require renewed consent after restarting the app, account changes or pausing.

Desktop reuses the running application's existing follow-through timer and latest-thread checks. Only explicitly tracked attention items with successful checks in the past 15 minutes and due times within the past day qualify. Cancelled/expired runs, inactive definitions, closed/paused items and failed checks do not qualify. A final parent/child check occurs after admission. At most 100 eligible candidates are examined per tick, rotating for fairness; at most five new submissions occur.

The same immutable provider namespace, selected enrolled Mac, native recovery session, destination hash and account-owned authoritative root must match. An old local-only root cannot be silently adopted for delivery. An existing gateway iMessage agent channel must be disabled and explicitly stopped; supported configuration writes are serialized against dispatch. No gateway agent framework is activated.

`ACCOUNT_IMESSAGE_DELIVERY_ENABLED` defaults off and requires the `imessage_delivery` migration after `imessage_intents`. A new scoped grant and permanent metadata-only event ledger use the existing signed API. Event identity hashes the follow-up ID and reviewed due time, scoped by owner; changing devices, setup requests, restarting or re-enabling does not bypass deduplication. One active destination grant per namespace is allowed. Delivery content and Apple address stay off the server.

A reservation commits before any send and is consumed even if the response is lost or a pre-send check fails. The native client rechecks remote grant revision, local suspension, latest parent/child state, and the exact self-thread. Admission expires after ten seconds; a send already admitted or in flight can finish during remote pause/revocation and cannot be recalled. Submission is not delivery proof. There is no automatic retry or SMS fallback. Uncertain, reserved and submitted-unverified outcomes must remain distinct from confirmed delivery; this version does not claim confirmed delivery.

Local pause cancels pending native work before network access and sets an in-memory fence independently of disk writes. Studio can pause the destination or disconnect it; these invalidate delivery grants when delivery is enabled. Device revoke and account authority changes fail admission. Offline Macs have no execution: reconnection can attempt only still-fresh reminders after consent, without replaying consumed events. Status reports local enablement, check errors and unverified submissions; it does not imply a running remote Mac.

There is no daemon, remote execution service, background Messages watcher, new provider grant or new recovery trust model. Real packaged transport, OS permissions, provider sessions and PostgreSQL behavior still require authorized staging verification. All development uses fixtures; no Messages operation or OS grant is part of test execution.
