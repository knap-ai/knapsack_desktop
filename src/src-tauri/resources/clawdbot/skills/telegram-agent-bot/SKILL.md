# Telegram Agent Bot — Knapsack Desktop

## When to use this skill

- A user activates an agent and asks to enable its Telegram interface
- An agent needs to send a message, summary, report, or file to a user via Telegram
- A new agent is added and needs a bot provisioned
- A token rotation is requested
- A user asks "set up Telegram for [agent name]"

## Architecture

Each Knapsack agent gets its own dedicated Telegram bot, created via the
Telegram Bot API 9.6 Managed Bots feature. A single **manager bot** (with
`can_manage_bots: true`) provisions and manages child bots for all agents.
OpenClaw's built-in Telegram channel integration handles all polling, message
routing, and delivery — no custom client code needed.

## Sending a message

Use the OpenClaw gateway's built-in channel tool. Do NOT make raw HTTP calls:

```
send_channel_message(
  channel="telegram",
  agent="<agentId>",
  chat_id=<chat_id>,
  text="<message>"
)
```

For streaming updates (live report progress):
```
edit_channel_message(
  channel="telegram",
  agent="<agentId>",
  chat_id=<chat_id>,
  message_id=<message_id>,
  text="<updated_text>"
)
```

For documents, PDFs, or DOCX output from a Knap workflow:
```
send_channel_file(
  channel="telegram",
  agent="<agentId>",
  chat_id=<chat_id>,
  file_path="<path>",
  caption="<caption>"
)
```

## Inline keyboard buttons (action menus)

Present action menus directly in Telegram:
```
send_channel_message(
  channel="telegram",
  agent="<agentId>",
  chat_id=<chat_id>,
  text="What would you like to do?",
  reply_markup={
    inline_keyboard: [[
      { text: "Run Report", callback_data: "action:run_report:<id>" },
      { text: "Export PDF", callback_data: "action:export_pdf:<id>" }
    ]]
  }
)
```

Callback data format: `action:<verb>:<target_id>` (max 64 bytes).

## Provisioning a bot for a new or renamed agent

When a user adds a new agent or asks to "set up Telegram for [agent name]":

1. Generate the deeplink for the user to create the managed bot in Telegram:
   ```
   https://t.me/newbot/<manager_bot_username>/knapsack_<agent_id>_bot
   ```
2. Instruct the user to open this link in Telegram and confirm bot creation
3. Once created, retrieve the bot token:
   ```
   npx ts-node scripts/provision-telegram-bots.ts --agent <agentId>
   ```
   This resolves the username → user_id, calls `getManagedBotToken`, and
   updates `openclaw.json` with the new channel entry.
4. Restart the gateway: `openclaw gateway restart`
5. Confirm: "✓ @knapsack_<agentid>_bot is live and routed to [Agent Name]"

## Token rotation

Rotate a compromised or expired token:
```
npx ts-node scripts/provision-telegram-bots.ts --rotate --agent <agentId>
```

For all agents at once:
```
npx ts-node scripts/provision-telegram-bots.ts --rotate
```

## Error handling

| Error | Action |
|-------|--------|
| `401 Unauthorized` | Token invalid or revoked — run token rotation |
| `429 Too Many Requests` | Wait `retry_after` seconds (from response body), then retry |
| Bot missing from gateway config | Re-run provisioner, restart gateway |
| `getManagedBotToken` fails | Confirm manager bot has `can_manage_bots: true` via `/getMe` |
| Bot not created yet | User must complete the `t.me/newbot/...` deeplink first |

## Security notes

- Bot tokens are stored as env vars (`TELEGRAM_TOKEN_<AGENT_ID_UPPER>`), never in plaintext config
- The `.telegram-tokens.env` file generated by the provisioner must not be committed (add to `.gitignore`)
- Manager bot token (`TELEGRAM_MANAGER_TOKEN`) grants full control of all child bots — treat as a root credential
