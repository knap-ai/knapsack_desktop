# Telegram Agent Bot — Knapsack Desktop

## Architecture

Each user gets five dedicated Telegram child bots (Chief of Staff + one per agent),
all provisioned under Knapsack's invisible manager bot (@knapsackspawnbot).
The manager bot is never shown to users.

Child bot usernames follow the pattern:
- Chief of Staff: `knapsack_{userSlug}_bot`
- Per-agent: `knapsack_{userSlug}_{agentSlug}_bot`

OpenClaw's built-in Telegram channel handles all polling, routing, and delivery.
Do NOT build custom polling loops or webhook handlers.

## When to use this skill

- Delivering this agent's scheduled output (daily summary, weekly report, morning brief)
- Sending a document, PDF, or DOCX generated by this agent's workflow
- Responding to a user message received on this agent's dedicated bot
- Sending a time-sensitive alert or notification

## Sending a message

Use the OpenClaw gateway — do NOT make raw HTTP calls:

```
send_channel_message(
  channel="telegram",
  agent="<this_agent_id>",
  chat_id=<user_chat_id>,
  text="<message>"
)
```

For streaming updates (live report progress):
```
edit_channel_message(
  channel="telegram",
  agent="<this_agent_id>",
  chat_id=<user_chat_id>,
  message_id=<message_id>,
  text="<updated_text>"
)
```

## Sending a file

```
send_channel_file(
  channel="telegram",
  agent="<this_agent_id>",
  chat_id=<user_chat_id>,
  file_path="<path>",
  caption="<description>"
)
```

## Inline keyboard buttons (action menus)

```
send_channel_message(
  channel="telegram",
  agent="<this_agent_id>",
  chat_id=<user_chat_id>,
  text="What would you like to do?",
  reply_markup={
    inline_keyboard: [[
      { text: "Run Report", callback_data: "action:run_report:<id>" },
      { text: "Export PDF", callback_data: "action:export_pdf:<id>" }
    ]]
  }
)
```

Callback data format: `action:<verb>:<target_id>` (max 64 bytes).

## Provisioning flow (UI)

1. User clicks "Set up →" for each agent on the Telegram onboarding screen
2. App opens `https://t.me/newbot/{manager}/{suggested}` via Tauri shell.open()
3. User creates the child bot in Telegram (~10 seconds)
4. App polls every 3 s until `getManagedBotToken` succeeds
5. Token written to `openclaw.json` and pushed to running gateway
6. UI shows "✓ @knapsack_{user}_{agent}_bot"

## Token rotation

Rotate silently (no user action required):
```
POST /api/clawd/telegram/agent-bot/rotate
{ "agent_id": "<agentId>" }
```

Or via CLI:
```bash
npx ts-node scripts/provision-telegram-bots.ts --rotate --agent <agentId>
```

## Error handling

| Error | Action |
|-------|--------|
| `401 Unauthorized` | Rotate via `POST /api/clawd/telegram/agent-bot/rotate` |
| `429 Too Many Requests` | Wait `retry_after` seconds from response body, then retry |
| `getManagedBotToken` fails | Child bot not created yet — user must complete the deeplink first |
| Bot missing from gateway config | Re-provision via onboarding |
| Manager bot lacks `can_manage_bots` | Contact Knapsack support |

## Security notes

- Bot tokens stored in `openclaw.json` (mode 600, app data dir) — never committed
- `TELEGRAM_MANAGER_TOKEN` grants control of all child bots — treat as root credential
- Child bot usernames include the user's slug for uniqueness across users
